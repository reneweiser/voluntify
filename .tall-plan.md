# Voluntify — Phase 2 Architecture Plan

## 1. Project Overview

Voluntify is a volunteer management platform for event-running organizations, built on Laravel 12 + Livewire 4 + Flux UI + Tailwind CSS 4. Phase 1 (milestones M1–M6) shipped the core product: event CRUD, passwordless volunteer signup, QR ticket scanning, attendance tracking, gear management, and an admin dashboard.

Phase 2 restructures the data model based on product-owner feedback (PR #89, issues #45–#88). The central change: **Event Groups become Projects** — a mandatory top-level entity that owns volunteers, gear, custom fields, and scanner configs. Events become children of Projects. The scanner and signup flow are rewritten as isolated modules. All other changes are incremental modifications to existing code.

**Key constraint:** The app is not in production. All current data is test data — `migrate:fresh` is always available. No data migration, backward compatibility, or rollback strategies are needed.

**Design spec:** `docs/review_voluntify-gesamtuebersicht.md` (868-line German overview from PR #89), plus `docs/decisions/2026-03-30-po-session.md` (10 PO decisions F1–F10).

---

## 2. Architecture Decision

**Keep Laravel default structure.** The existing codebase uses `app/Actions/`, `app/Livewire/`, `app/Models/`, `app/Policies/`, `app/Services/` — no DDD layers. This is correct: <20 models, small team, business logic fits in Actions + Form objects. No change needed.

**Existing pattern to preserve:** Single-responsibility Action classes with `execute()` method (not `__invoke()`). All existing Actions use `execute()` — maintain consistency.

### 3.2 Model Changes by Milestone

#### Milestone M7: Foundation

**Rename `event_groups` → `projects`:**
- Drop `event_groups` table, create `projects` table with same columns + any additions
- Columns: `id`, `organization_id` (FK), `name`, `public_token` (unique), `description`, `title_image_path`, `created_at`, `updated_at`
- New model: `App\Models\Project` (replaces `EventGroup`)
- `HasTitleImage` trait remains

**Modify `events` table:**
- Rename `event_group_id` → `project_id` (FK to `projects`, `cascadeOnDelete`, NOT NULL)
- Add `status` expansion: `draft`, `published_open`, `published_closed`, `archived` (replaces current 3-state `EventStatus` enum)
- Drop index on old FK, add index on `project_id`

**Modify `volunteers` table:**
- Split `name` → `first_name`, `last_name` (both required, string)
- Drop `name` column
- Update `$fillable`, factory, search scope (FULLTEXT on `first_name`, `last_name`, `email`)

**Modify `events` table (phone config):**
- Add `phone_required` (boolean, default `false`)

#### Milestone M8: Project-Scoped Data

**Add `visibility` to `events` table (Private Events #91):**
- Add `visibility` enum column: `public` (default), `private`
- New enum: `App\Enums\EventVisibility` (Public, Private)
- Private events excluded from ProjectWebsite listing
- Private events don't trigger project website activation on first publish
- Toggle changeable anytime; all other behavior (signup, QR, gear, scanner) identical

**Modify `volunteers` table:**
- Add `project_id` (FK to `projects`, `cascadeOnDelete`, NOT NULL)
- Add unique index on `['email', 'project_id']`
- Update `$fillable`

**Rename `event_gear_items` → `project_gear_items`:**
- Replace `event_id` FK with `project_id` FK
- Add `type` enum column: `size_selection` (Typ 1), `quantity` (Typ 2)
- Add `states` (json, nullable) — configurable state list for Typ 1
- New model: `App\Models\ProjectGearItem` (replaces `EventGearItem`)

**Add `volunteer_gear_pickups` table (NEW):**
- `id`, `volunteer_gear_id` (FK), `picked_up_by` (nullable, FK to users), `picked_up_at` (datetime), `state` (string, nullable — for Typ 1), `quantity` (integer, default 1 — for Typ 2)
- Tracks individual pickup events (replaces `picked_up_at`/`picked_up_by` on `volunteer_gear`)

**Modify `volunteer_gear` table:**
- Replace `event_gear_item_id` FK with `project_gear_item_id` FK
- Drop `picked_up_at`, `picked_up_by` (moved to `volunteer_gear_pickups`)

**Modify `custom_registration_fields` table:**
- Add `project_id` (FK, nullable) alongside existing `event_id` (nullable)
- Constraint: exactly one of `project_id` or `event_id` must be non-null

**Modify `tickets` table:**
- Replace `event_id` FK with `project_id` FK
- One ticket per volunteer per project (unique on `['volunteer_id', 'project_id']`)

**Modify `JwtKeyService`:**
- Key derivation changes from `eventId:periodDate` to `projectId:periodDate`

#### Milestone M9: Roles & Team

**Modify `organization_user` pivot:**
- Role model change: only `Organizer` role stored at org level
- `VolunteerAdmin` and `EntranceStaff` are no longer org-level roles — they're scanner assignees

**Update `StaffRole` enum:**
- Keep `Organizer` at org level
- `VolunteerAdmin` and `EntranceStaff` become scanner-assignment concepts, not org roles

**Add `project_user` pivot table (NEW):**
- `project_id`, `user_id`, `role` (enum: `organizer`)
- Org-level Organizers auto-inherit project access

#### Milestone M10: Signup Flow

**Add `shift_reservations` table (NEW):**
- `id`, `shift_id` (FK), `session_id` (string), `expires_at` (datetime)
- 20-minute TTL, counts against shift capacity
- Cleanup via scheduled command

**Modify `email_verification_tokens` table:**
- Add `project_id` (FK) for project context during verification
- Keep existing `shift_ids`, `gear_selections` json columns

#### Milestone M11: Scanner

**Add `project_scanners` table (NEW):**
- `id`, `project_id` (FK), `type` (enum: `entry_staff`, `volunteer_admin`)
- `scope` (enum: `event`, `project`), `event_id` (FK, nullable — when scoped to single event)
- `modes` (json: `['checkin', 'gear_pickup']`)
- `gear_item_ids` (json, nullable — which items this scanner distributes)
- `hint_text` (text, nullable)
- `starts_at`, `ends_at` (datetime — time window)
- `auth_code` (string, hashed — one-time auth)
- `status` computed from time window: `scheduled`/`active`/`expired`

**Add `project_scanner_assignees` table (NEW):**
- `id`, `project_scanner_id` (FK), `email` (string)
- `link_sent_at` (datetime, nullable), `authenticated_at` (datetime, nullable)

#### Milestone M12: Guest Lists (#90)

**Add `guest_lists` table (NEW):**
- `id`, `project_id` (FK), `scanner_id` (FK → `project_scanners`, Entry Staff type required)
- `name` (string), `status` (enum: `draft`, `confirmed`)
- `gear_items` (json, nullable — which gear items are available for this list)

**Add `guest_groups` table (NEW):**
- `id`, `guest_list_id` (FK, cascadeOnDelete)
- `label` (string, e.g. "DJ Soundwave"), `guest_count` (integer)

**Add `guest_entries` table (NEW):**
- `id`, `guest_group_id` (FK, cascadeOnDelete), `number` (integer)
- `name` (string, nullable), `email` (string, nullable)
- `qr_token` (string, nullable — generated on confirmation), `checked_in_at` (datetime, nullable)

**Add `guest_entry_gear` table (NEW):**
- `id`, `guest_entry_id` (FK, cascadeOnDelete), `project_gear_item_id` (FK)
- `quantity` (integer, default 1 — Typ-2), `picked_up_count` (integer, default 0 — Typ-2)
- `selection` (string, nullable — Typ-1 size choice), `status` (string, nullable — Typ-1 state)

## 4. Authorization Model

### 4.1 Roles

| Role | Scope | How Assigned | Persistent Account? |
|---|---|---|---|
| **Organizer** | Organization + all Projects | Invited via email, creates User account | Yes |
| **Project Organizer** | Specific Project only | Invited or promoted | Yes |
| **Volunteer Admin** | Scanner assignment | Email link, one-time code | No — temp scanner link |
| **Entry Staff** | Scanner assignment | Email link, one-time code | No — temp scanner link |
| **Volunteer** | Project membership | Passwordless signup | No |

### 4.2 Policy Changes

**New: `ProjectPolicy`** (replaces `EventGroupPolicy`):
- `viewAny(User, Organization)` — any org member
- `view(User, Project)` — any org member OR project member
- `create(User, Organization)` — Organizer only
- `update(User, Project)` — Organizer OR Project Organizer
- `delete(User, Project)` — Organizer only
- `manageGear(User, Project)` — Organizer OR Project Organizer
- `manageScanners(User, Project)` — Organizer OR Project Organizer
- `manageCustomFields(User, Project)` — Organizer OR Project Organizer

**Modified: `EventPolicy`:**
- All methods check project membership instead of direct org role
- `scan()` method removed (scanning is now per-ProjectScanner, not per-Event)
- Add `manageSettings(User, Event)` — Organizer/Project Organizer

**Scanner authorization:**
- No policy — scanner access is validated via `ProjectScanner` auth code + time window
- `ProjectScannerAssignee` email match + valid auth code + active time window = access granted

### 4.3 Data Scoping

- Volunteers scoped by `project_id` (not global)
- Gear items scoped by `project_id`
- Custom fields: project-level fields shared across events, event-level fields per-event
- Tickets scoped by `project_id` (one per volunteer per project)
- Scanner configs scoped by `project_id`

## 9. API Design

### Scanner API (modified)

The existing scanner API at `/admin/scanner/api/` changes to project-scoped, scanner-authenticated endpoints:

```
GET  /api/scanner/{scannerId}/data       → volunteer list + keys for this scanner's scope
POST /api/scanner/{scannerId}/sync        → sync arrivals/check-ins from offline queue
POST /api/scanner/{scannerId}/gear-pickup → record gear state change (online-only for Typ 2)
```

Authentication: scanner token (from `ProjectScanner.auth_code`) instead of Fortify session.

No other API changes. No public API needed for MVP.
