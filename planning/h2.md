# Plan: Introduce Livewire Form Objects for Complex Components

## Context

3 Livewire components have 8+ validated fields with inline `$this->validate([...])` calls. No Form Objects exist in the project (`app/Livewire/Forms/` doesn't exist). Extracting Form Objects improves validation reuse, state management, and testability. The project already uses a trait-based validation pattern (`PasswordValidationRules`, `ProfileValidationRules`) — Form Objects are the natural Livewire v4 evolution of this.

---

## Components to Refactor

### 1. EventSettings (10 fields, 1 form state)

**Current fields:** `$name`, `$description`, `$location`, `$startsAt`, `$endsAt`, `$titleImage`, `$attendanceGraceMinutes`, `$visibility`, `$notificationEmail`, `$selectedProjectId`

**File:** `app/Livewire/Events/EventSettings.php`

**Form Object:** `app/Livewire/Forms/EventSettingsForm.php`

**Fields to extract (9 — excluding `$selectedProjectId` which triggers a separate action):**
```php
class EventSettingsForm extends Form
{
    #[Validate('required|string|max:255')]
    public string $name = '';

    #[Validate('nullable|string')]
    public string $description = '';

    #[Validate('nullable|string|max:255')]
    public string $location = '';

    #[Validate('required|date')]
    public string $startsAt = '';

    #[Validate('required|date|after:startsAt')]
    public string $endsAt = '';

    #[Validate('nullable|image|mimes:jpg,jpeg,png,webp|max:2048')]
    public $titleImage = null;

    #[Validate('nullable|integer|min:0|max:120')]
    public $attendanceGraceMinutes = '';

    #[Validate('required')]  // + Rule::in(EventVisibility) in rules() method
    public string $visibility = 'public';

    #[Validate('nullable|email|max:255')]
    public string $notificationEmail = '';
}
```

**Component change:** Replace 9 public properties with `public EventSettingsForm $form`. Update `saveEvent()` to use `$this->form->validate()` and `$this->form->propertyName`. Update `fillForm()` to use `$this->form->fill(...)`. Update blade from `$name` to `$form.name` etc.

**Note:** The `Rule::in(EventVisibility::cases())` validation rule is dynamic — use a `rules()` method override on the Form Object rather than the `#[Validate]` attribute for `$visibility`.

### 2. ScannerManagement (8 fields, 1 form state + modal)

**Current fields:** `$name`, `$type`, `$modes`, `$eventId`, `$gearItemIds`, `$hintText`, `$startsAt`, `$endsAt`

**File:** `app/Livewire/Projects/ScannerManagement.php`

**Form Object:** `app/Livewire/Forms/ScannerForm.php`

**Fields to extract (all 8):**
```php
class ScannerForm extends Form
{
    #[Validate('required|string|max:255')]
    public string $name = '';

    #[Validate('required|string|in:entry_staff,volunteer_admin')]
    public string $type = 'entry_staff';

    #[Validate('required|array|min:1')]
    public array $modes = ['checkin'];

    public ?int $eventId = null;  // validated dynamically (Rule::exists with project scope)

    public array $gearItemIds = [];  // not currently validated

    public string $hintText = '';  // not currently validated

    #[Validate('required|date')]
    public string $startsAt = '';

    #[Validate('required|date|after:startsAt')]
    public string $endsAt = '';
}
```

**Component change:** Replace 8 properties with `public ScannerForm $form`. Both `createScanner()` and `updateScanner()` currently duplicate the same validation rules — the Form Object eliminates this duplication. Update `editScanner()` to use `$this->form->fill(...)` and `resetForm()` to use `$this->form->reset()`.

**Note:** `$eventId` uses `Rule::exists('events', 'id')->where('project_id', $this->projectId)` — this needs the component's `$projectId` context. Use a `rules()` method on the Form that accepts the project ID, or validate `eventId` separately in the component.

## Shared Validation Patterns

The image validation rule `['nullable', 'image', 'mimes:jpg,jpeg,png,webp', 'max:2048']` appears in all 3 components. The date range pattern (`required|date` + `required|date|after:startsAt`) also repeats. These could become shared rule methods on a base Form class or trait, but that's optional — start with standalone Form Objects and extract shared rules only if a fourth consumer appears.

## Execution Order

1. **ScannerForm** — cleanest extraction (duplicate validation removed, single form state)
2. **EventSettingsForm** — straightforward (single form state, 9 fields)
3. **ProjectDetailsForm + CreateEventInProjectForm** — most complex (multi-form component)

## Blade View Changes

All blade views need property references updated: `$name` → `$form.name` (or `$projectForm.name` for ProjectShow). Wire model bindings: `wire:model="name"` → `wire:model="form.name"`. Error references: `@error('name')` → `@error('form.name')`.
