# Plan: Test Coverage for 5 Untested Livewire Components

## Context

5 Livewire components have zero test coverage. Two are security-sensitive (`DeleteUserForm`, `RecoveryCodes`), one is public-facing (`JobCheatSheet`), and two are low-risk (`Logout`, `Appearance`). `DeleteUserForm` and `RecoveryCodes` already have partial indirect coverage in `ProfileUpdateTest` and `TwoFactorAuthenticationTest` respectively — this plan fills the gaps.

---

## Components

### 1. DeleteUserForm (`app/Livewire/Settings/DeleteUserForm.php`)

**What it does:** Password-confirmed permanent user account deletion + logout + redirect.

**Existing partial coverage:** `tests/Feature/Settings/ProfileUpdateTest.php` (2 tests: success + wrong password). Gaps: logout verification, session invalidation, unauthenticated access.

**New test file:** `tests/Feature/Settings/DeleteUserFormTest.php`

**Tests to write:**
```
it('deletes user account with correct password')
it('rejects incorrect password with validation error')
it('rejects empty password')
it('logs user out after deletion')
it('redirects to home after deletion')
it('user no longer exists in database after deletion')
```

**Setup:** `actingAs(User::factory()->create(['password' => 'password']))`, test via `Livewire::test(DeleteUserForm::class)`.

---

### 2. RecoveryCodes (`app/Livewire/Settings/TwoFactor/RecoveryCodes.php`)

**What it does:** Displays decrypted 2FA recovery codes. Has `regenerateRecoveryCodes()` that calls Fortify's `GenerateNewRecoveryCodes` action. Uses `#[Locked]` on `$recoveryCodes` array. Catches decryption exceptions gracefully.

**Existing partial coverage:** `tests/Feature/Settings/TwoFactorAuthenticationTest.php` (1 test: component renders when 2FA not enabled).

**New test file:** `tests/Feature/Settings/TwoFactor/RecoveryCodesTest.php`

**Tests to write:**
```
it('loads recovery codes when two factor is enabled')
it('shows empty codes when two factor is not enabled')
it('regenerates new recovery codes')
it('handles decryption failure gracefully')
```

**Setup:** Need a user with 2FA enabled — check if `TwoFactorAuthenticationTest` has a helper or if we need to enable 2FA via Fortify actions. The `$recoveryCodes` property is `#[Locked]`, so test via rendered output or `assertSet`.

---

### 3. JobCheatSheet (`app/Livewire/Public/JobCheatSheet.php`)

**What it does:** Public page showing volunteer job instructions. Mounts with `$publicToken` + `$jobId`. Queries `Event::publishedByToken()`, filters jobs to those with non-empty instructions, finds the specific job. Uses `layouts.public`.

**New test file:** `tests/Feature/Public/JobCheatSheetTest.php`

**Tests to write:**
```
it('displays job instructions for valid published event')
it('returns 404 for invalid public token')
it('returns 404 for job without instructions')
it('returns 404 for job not belonging to event')
it('returns 404 for unpublished event')
```

**Setup:** `Event::factory()->published()->create()` with a `VolunteerJob` that has instructions. No auth needed (public route).

---

### 4. Logout (`app/Livewire/Actions/Logout.php`)

**What it does:** Logs out user (web guard), invalidates session, regenerates token, redirects to `/`.

**New test file:** `tests/Feature/Actions/LogoutTest.php`

**Tests to write:**
```
it('logs out the authenticated user and redirects to home')
```

**Setup:** `actingAs($user)`, call the component, assert redirect and `Auth::check()` is false.

---

### 5. Appearance (`app/Livewire/Settings/Appearance.php`)

**What it does:** Empty component — just renders with title "Appearance settings". No logic.

**New test file:** `tests/Feature/Settings/AppearanceTest.php`

**Tests to write:**
```
it('renders the appearance settings page')
```

**Setup:** `actingAs($user)`, `Livewire::test(Appearance::class)`, `assertOk()`.

---

## Execution Order

1. `DeleteUserForm` (security-sensitive, highest priority)
2. `RecoveryCodes` (security-sensitive)
3. `JobCheatSheet` (public-facing)
4. `Logout` (1 test)
5. `Appearance` (1 test)
